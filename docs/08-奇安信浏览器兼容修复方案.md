# Ant Design 5 兼容奇安信等政企浏览器方案

> 本文用于解决政企定制浏览器（奇安信、部分 360 浏览器，Chromium 69~86 内核）下页面样式大面积丢失的问题；适用对象为本项目当前的 UmiJS Max 4 + Ant Design 5 前端。
>
> 与 mall 项目（Vite + React + Tailwind v4）的根因不同：本项目不使用 Tailwind，问题出在 Ant Design 5 的运行时 CSS-in-JS。

## 审核结论

**可以解决，且无需降级任何依赖。** 只需在 `.umirc.ts` 中增加两处配置（`targets` 与 `antd.styleProvider`），重新构建发布即可。

### 根因分析

对现有构建产物逐项排查后确认：

| 检查项 | 结论 |
| --- | --- |
| 静态 CSS（`dist/*.css`） | 干净。`@layer` / `@property` / `color-mix()` / `oklch()` / `:where()` 均为 0 |
| JS 现代语法（`?.` / `??`） | 无真实使用（匹配到的均为数字三元表达式与 xlsx 数字格式字符串） |
| JS 现代 API（`structuredClone` / `.findLast` / `.at()`） | 已由 core-js 按 `targets` 自动注入 polyfill |
| `globalThis` | 均有 `typeof globalThis === "object"` 防护，可安全回退 |
| **Ant Design 5 运行时样式** | **真正的根因** |

Ant Design 5（@ant-design/cssinjs）默认 `hashPriority: 'low'`，会把**全部组件样式**的选择器包裹成 `:where(.css-hash)`：

```js
// @ant-design/cssinjs/lib/hooks/useStyleRegister.js
var hashSelector = hashPriority === 'low' ? ":where(".concat(hashClassName, ")") : hashClassName;
```

`:where()` 需要 **Chrome 88+**。奇安信浏览器内核为 69~86，遇到不认识的 `:where()` 会**整条规则直接跳过**，导致按钮、表格、表单、布局、颜色、间距等 antd 样式全部失效——这正是"DOM 和文字存在、但样式大面积丢失，Chrome 正常"的现象。

> 本项目 antd 组件样式是**运行时**由 CSS-in-JS 注入的，不在静态 CSS 文件里，所以只检查 `dist/*.css` 看不出问题，必须从 cssinjs 的生成逻辑入手。

## 已实施的修改

仅改动 `frontend/.umirc.ts` 一个文件：

```ts
export default defineConfig({
    npmClient: 'npm',
    title: '穿透式监督查询系统',
    // 兼容奇安信等政企浏览器（Chromium 69~86 内核）。
    // Umi 默认 targets 为 chrome 80；降到 69 以确保 JS 语法转译 + CSS 前缀覆盖最低内核。
    targets: { chrome: 69 },
    antd: {
        configProvider: {},
        // Ant Design 5 默认用 :where(.css-hash) 包裹全部组件样式（需 Chrome 88+），
        // 奇安信浏览器内核低于 88 时会整体跳过这些规则，导致样式大面积丢失。
        // hashPriority: 'high' 改用普通 .css-hash 类选择器（全内核兼容）；
        // legacyTransformer: true 将 CSS 逻辑属性（inset-block-start 等）转为旧写法。
        styleProvider: {
            hashPriority: 'high',
            legacyTransformer: true,
        },
    },
    // ... 其余配置不变
});
```

### 各配置的作用

- **`targets: { chrome: 69 }`**：Umi 默认目标是 `chrome: 80`。降到 69 后，Babel 会把源码中可能出现的 `?.` / `??` 等新语法转译为旧写法，core-js 会补齐 Chrome 69~79 缺失的 API，CSS 前缀也按 69 生成。属于防御性加固。
- **`styleProvider.hashPriority: 'high'`**：**核心修复**。让 cssinjs 放弃 `:where(.css-hash)`，改用普通 `.css-hash` 类选择器，全部内核可解析。
- **`styleProvider.legacyTransformer: true`**：启用 `legacyLogicalPropertiesTransformer`，把 `inset-block-start`、`margin-inline-start` 等 CSS 逻辑属性转成 `top`、`margin-left` 等旧写法（逻辑属性需 Chrome 87+）。

Umi 的 antd 插件会在生产构建时据此自动生成带 `<StyleProvider hashPriority="high" transformers={[legacyLogicalPropertiesTransformer]}>` 的根容器（见 `src/.umi-production/plugin-antd/runtime.tsx`），无需手写任何运行时代码。

### 副作用说明

- `hashPriority: 'high'` 会让 antd 选择器从 0 优先级（`:where`）变为普通类优先级，理论上更难被外部样式覆盖。本项目 `global.css` 的覆盖均使用 `!important` 或更高优先级选择器，不受影响。
- `targets: { chrome: 69 }` 会略微增大 polyfill 体积（gzip 后增量很小），可接受。

## 构建与验证

```powershell
cd frontend
npm run build
```

构建成功后，用以下命令快速自检（PowerShell）：

```powershell
# 静态 CSS 不应含任何现代特性（无输出为通过）
Get-ChildItem dist -Filter '*.css' | Select-String -Pattern '@layer|@property|color-mix\(|oklch\(|:where\(|:is\('

# 主包应包含 hashPriority:"high" 配置点（应输出 1 处）
Get-ChildItem dist -Filter 'umi.*.js' | Select-String -Pattern 'hashPriority:\s*"high"'
```

已验证结果：

- 静态 CSS：`@layer` / `@property` / `color-mix` / `oklch` / `:where` / `:is(` 全部为 0 ✅
- JS：真实 `?.` / `??` 为 0 ✅
- 主包含 `hashPriority:"high"` 配置点 ✅
- 产物中残留的 2 处 `:where(` 均为 cssinjs 库内部代码（一处是特性检测的测试字符串，一处是 `hashPriority==='low'` 才走的分支，已不会执行）✅

## 部署

1. 本地 `npm run build` 完成上述自检。
2. 上传**完整的** `frontend/dist/` 到服务器（不要只传 `index.html` 或单个资源，避免 HTML 引用与哈希资源不一致）。
3. 用无痕窗口或 Ctrl+F5 分别在 Chrome 与奇安信浏览器验证。文件名带 hash，旧资源不会被新 HTML 复用，但旧标签页应关闭或强刷。

## 仍需注意的边界情况

- **Flexbox `gap`（Chrome 84+）**：antd 5 部分组件用 `gap` 控制间距。若奇安信内核低于 84，个别间距会偏紧，但**不影响功能与整体布局**（与 `:where` 导致的整体失效是两回事）。如确认内核 < 84 且对间距敏感，再针对性补充 margin 回退。
- **先确认内核版本**：在奇安信浏览器打开控制台或版本页，记录 Chromium 版本。若已是 88+，则 `:where` 不是根因，应另查 Nginx MIME / 资源路径。

## 回滚

改动只涉及 `.umirc.ts`。回滚时删除 `targets` 与 `antd.styleProvider` 两段，重新 `npm run build` 发布即可（或恢复该文件的 Git 历史版本）。

## 不建议的单独措施

- **只改 Nginx MIME / charset**：只能修复响应头问题，不能让 Chrome 69~86 解析 `:where()`。
- **降级到 antd 4**：antd 4 用静态 CSS 确实无此问题，但需要大规模改写组件与主题代码，成本远高于本方案，不推荐。
- **只设 `targets`**：只处理 JS 与 CSS 前缀，不处理运行时 CSS-in-JS 的 `:where()`，无法修复本问题。

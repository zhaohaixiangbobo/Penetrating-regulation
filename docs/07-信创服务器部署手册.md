# 穿透式监督查询系统 · 信创服务器部署手册

> 适用环境：**aarch64（ARM64）+ 统信 UOS Server 20**
> 网络：**配置阶段可临时联网**（装完即可关闭，生产运行不依赖外网）
> 部署形态：**Nginx（80 端口）托管前端 + 反向代理 → uvicorn（FastAPI 纯 API）**,systemd 守护 + 开机自启
> 数据库：StarRocks（已部署于 `10.9.14.128:9030`，本手册不涉及其安装）

---

## 一、部署架构与方案说明

```
              浏览器（用户电脑）
                   │  http://<服务器IP>:80
                   ▼
 ┌──────────────────────────────────────────────┐
 │         信创服务器 (aarch64 / UOS20)            │
 │                                                │
 │   Nginx (systemd)  监听 0.0.0.0:80             │
 │     ├─ location /       前端静态资源(SPA回退)    │
 │     │      root /opt/shenji/frontend/dist       │
 │     └─ location /api/   反向代理 ↓              │
 │                proxy_pass http://127.0.0.1:8000 │
 │                          │                      │
 │   uvicorn (systemd)  监听 127.0.0.1:8000        │
 │     └─ FastAPI 纯 API 服务 (/api/*)             │
 └──────────────────────────────────────────────┘
                   │  MySQL 协议 (aiomysql 驱动)
                   ▼
      StarRocks  10.9.14.128:9030  (eap_adb)
```

针对「aarch64 + 配置期临时联网」的环境，本方案做了如下取舍（**重要，请先理解**）：


| 关键点          | 方案                                                                                                | 原因                                                                                                                                                                 |
| --------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **代码管理**    | GitHub 仓库 + 服务器`git clone` 到 `/opt/shenji`                                                    | 版本可追溯，后续更新只需`git pull`，无需反复打包传输                                                                                                                 |
| **Python 3.12** | 用[python-build-standalone](https://github.com/astral-sh/python-build-standalone/releases) 预编译包 | UOS20 自带 Python 3.7 过低；预编译包**免编译、免系统依赖**，解压即用，最稳妥                                                                                         |
| **数据库驱动**  | 用`aiomysql`（纯 Python）替代 `asyncmy`                                                             | `asyncmy` 是 Cython 编译产物，**无稳定 aarch64 wheel**，即便联网也需现场编译、风险高；`aiomysql` 纯 Python，任意架构直接安装。本系统为低并发内部工具，性能差异可忽略 |
| **Web 服务器**  | **Nginx** 托管前端静态资源 + 反向代理 `/api`                                                        | 配置期可临时联网，`apt install nginx` 一步到位；Nginx 抗并发、静态资源缓存、SPA 回退更专业，是生产标准架构                                                           |
| **依赖安装**    | 配置期**临时联网**直接 `pip install`（推荐国内镜像加速）                                            | 比离线下载 wheel 简单得多；装完即可断网，生产运行不再联网                                                                                                            |

> 临时联网只需在「git clone + 装 Python 依赖 + 装 Nginx」这几步期间保持，全部装完即可关闭网络，系统在内网独立运行。

## 二、准备工作（在【联网电脑 / Windows 开发机】上操作）

> 在你的 Windows 开发机（已装 Node.js）上完成，产出 2 样东西：Python 解释器包、前端构建产物。
> 后端代码通过 GitHub 仓库获取（见第三节），**无需**再手动打包 backend。
> 依赖 wheel **无需**在此预下载——服务器临时联网时直接 pip 安装即可（见 4.2）。

### 2.1 下载 Python 3.12（aarch64 预编译包）

1. 打开 [https://github.com/astral-sh/python-build-standalone/releases](https://github.com/astral-sh/python-build-standalone/releases)
2. 在最新 release 里找到文件名形如：
   ```
   cpython-3.12.X+YYYYMMDD-aarch64-unknown-linux-gnu-install_only.tar.gz
   ```

   （`3.12.X` 取最新的 3.12 小版本，`YYYYMMDD` 是构建日期；**务必选 `aarch64` + `install_only`**）
3. 下载后重命名为 `python3.12-aarch64.tar.gz` 备用。

> 若服务器临时联网期间访问 GitHub 方便，也可跳过本步，直接在服务器上 `wget` 下载该包（见 4.1 备注）。

### 2.2 构建前端

```powershell
cd d:\2-code\shenji\frontend
npm run build
```

构建产物在 `frontend/dist/`（已被 `.gitignore` 排除，不会上传到 GitHub）。

> 前端接口请求用的是相对路径 `/api/*`，经 Nginx 同源代理，无需任何改动，也不存在跨域问题。

### 2.3 推送代码到 GitHub

```powershell
cd d:\2-code\shenji
git add .
git commit -m "feat: 穿透式监督查询系统"
git remote add origin https://github.com/<你的用户名>/shenji.git   # 仅首次
git push -u origin main
```

> `.gitignore` 已排除 `.env`、`data/`、`node_modules/`、`dist/`、`__pycache__/` 等敏感/冗余文件，可放心推送。

### 2.4 传输前端构建产物与 Python 包

`frontend/dist/` 和 Python 解释器包不在 Git 仓库中，需单独传到服务器：

```powershell
# 在 Windows PowerShell 执行（服务器已开 SSH）
scp -r d:\2-code\shenji\frontend\dist root@<服务器IP>:/opt/shenji-frontend-dist

scp -r d:\2-code\shenji\frontend\dist root@10.9.14.144:/opt/shenji/frontend/dist

scp d:\python3.12-aarch64.tar.gz root@<服务器IP>:/opt/
```

> 也可用 U 盘拷贝。Python 包若服务器能访问 GitHub，也可在服务器上直接 wget（见 4.1 备注）。

## 三、获取代码到服务器（临时联网）

### 方式一：git clone（推荐）

服务器临时联网期间，直接从 GitHub 克隆仓库到 `/opt/shenji`：

```bash
ssh root@<服务器IP>

# 安装 git（UOS20 一般已预装，若没有则临时联网安装）
apt install -y git

# 克隆仓库到程序运行目录
git clone https://github.com/<你的用户名>/shenji.git /opt/shenji
```

> 若仓库为 **私有仓库**，clone 时需要认证，二选一：
>
> - HTTPS + Token：`git clone https://<用户名>:<Personal-Access-Token>@github.com/<用户名>/shenji.git /opt/shenji`
> - SSH 密钥：在服务器 `ssh-keygen -t ed25519`，把 `~/.ssh/id_ed25519.pub` 添加到 GitHub → Settings → SSH Keys，然后 `git clone git@github.com:<用户名>/shenji.git /opt/shenji`

克隆完成后，`/opt/shenji/backend/` 即为后端代码，无需再手动复制。

### 方式二：手动传输（无 GitHub 访问时备选）

若服务器无法访问 GitHub，仍可用 scp / U 盘传输：

```powershell
# Windows PowerShell：把整个项目（排除 node_modules/dist）打包
scp d:\shenji-deploy.zip root@<服务器IP>:/opt/
```

```bash
# 服务器上解压
cd /opt
unzip shenji-deploy.zip -d shenji
```

> 下文统一约定：程序运行目录为 `/opt/shenji`，Python 解释器为 `/opt/shenji-python`。

## 四、服务器安装（在【信创服务器】上操作，root 用户）

> ⚠️ **从本步开始请保持服务器临时联网**，直到 4.2（pip 装依赖）与 4.6（apt 装 Nginx）完成。

### 4.1 安装 Python 3.12（免编译）

```bash
mkdir -p /opt/shenji-python
tar -xzf /opt/python3.12-aarch64.tar.gz -C /opt/shenji-python --strip-components=1

# 验证
/opt/shenji-python/bin/python3.12 --version    # 应输出 Python 3.12.x
```

> `--strip-components=1` 会去掉压缩包顶层的 `python/` 目录，使二进制位于 `/opt/shenji-python/bin/`。
> 备注：若临时联网且能访问 GitHub，也可在服务器直接下载：
>
> ```bash
> wget https://github.com/astral-sh/python-build-standalone/releases/download/20250317/cpython-3.12.9+20250317-aarch64-unknown-linux-gnu-install_only.tar.gz \
>   -O /opt/python3.12-aarch64.tar.gz
> ```
>
> 然后执行上面的 tar 解压命令。

### 4.2 创建虚拟环境并安装依赖（临时联网）

```bash
# 创建虚拟环境（venv 在 .gitignore 中，不会影响 git 仓库）
/opt/shenji-python/bin/python3.12 -m venv /opt/shenji/venv

# 临时联网直接安装（用清华镜像加速；装完即可断网）
/opt/shenji/venv/bin/pip install --upgrade pip -i https://pypi.tuna.tsinghua.edu.cn/simple
/opt/shenji/venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
  -r /opt/shenji/backend/requirements-server.txt

# 验证关键包
/opt/shenji/venv/bin/python -c "import fastapi, uvicorn, aiomysql, sqlalchemy; print('deps ok')"
```

> 若公司内网只能访问指定镜像，把 `-i` 后的地址换成可用镜像即可。
> 若临时联网受限无法 pip 在线安装，改用【附录 B：离线 wheel 安装（备选）】。

### 4.3 放置前端构建产物

后端代码已通过 `git clone` 就位于 `/opt/shenji/backend/`，无需额外操作。
前端 `dist/` 被 `.gitignore` 排除，需单独放置：

```bash
# 将 2.4 步传来的前端构建产物移到 Nginx 托管目录
mkdir -p /opt/shenji/frontend
mv /opt/shenji-frontend-dist /opt/shenji/frontend/dist

# 确认前端入口存在
ls /opt/shenji/frontend/dist/index.html
```

> 若使用 U 盘传输，把 dist 目录拷贝到 `/opt/shenji/frontend/dist` 即可。

### 4.4 配置环境变量

```bash
cd /opt/shenji/backend
cp .env.example .env
vi .env
```

重点修改两项：

```ini
# 1) StarRocks 连接（确认 IP/端口/密码正确，密码中 # 已编码为 %23）
STARROCKS_URL=mysql+aiomysql://root:TJycrock%23lc2025@10.9.14.128:9030/eap_adb?charset=utf8mb4

# 2) JWT 密钥务必改为随机长字符串（在 shell 里执行 openssl rand -hex 32 生成后粘贴）
JWT_SECRET=粘贴生成的随机串
```

### 4.5 初始化本地数据库（创建 admin 账号）

```bash
cd /opt/shenji/backend
/opt/shenji/venv/bin/python -m scripts.init_db
# 输出 [ok] 已创建默认用户: admin
```

> 默认登录账号 `admin`，密码 `tjyc!2026`（首次登录后建议修改）。

### 4.6 安装并配置 Nginx（临时联网）

```bash
# 安装 Nginx
apt update
apt install -y nginx

# 移除默认站点，避免占用 80 端口冲突
rm -f /etc/nginx/sites-enabled/default
```

> 若 `apt install nginx` 因软件源不可用而失败：可挂载 UOS 安装 ISO 作为本地 apt 源后重试，
> 或在另一台联网的同架构机器上 `apt download nginx nginx-common libnginx-mod-*` 下载 deb 包拷回 `dpkg -i *.deb`。

创建站点配置：

```bash
vi /etc/nginx/conf.d/shenji.conf
```

写入以下内容：

```nginx
server {
    listen 80;
    server_name _;

    # 前端静态资源 + SPA 路由回退
    root /opt/shenji/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存（带扩展名的资源直出并缓存）
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public";
    }

    # 后端接口反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;    # 导出大数据量时避免超时
    }
}
```

校验配置：

```bash
nginx -t        # 输出 syntax is ok / test is successful 即正确
```

### 4.7 手动启动联调

```bash
# 1) 手动起后端（临时进程，验证用）
cd /opt/shenji/backend
/opt/shenji/venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 &

# 2) 直连后端验证
curl http://127.0.0.1:8000/api/health        # 应返回 {"status":"ok"}

# 3) 启动 Nginx
systemctl start nginx

# 4) 经 Nginx 验证（80 端口）
curl http://127.0.0.1/api/health             # 应返回 {"status":"ok"}
curl -I http://127.0.0.1/                    # 应返回 HTTP/1.1 200（index.html）
```

确认无误后，停掉手动起的后端临时进程（`kill %1` 或 `pkill -f "uvicorn app.main:app"`），进入下一步用 systemd 托管。

## 五、systemd 守护 + 开机自启

### 5.1 后端服务（uvicorn）

创建服务文件：

```bash
vi /etc/systemd/system/shenji.service
```

写入以下内容（**注意 host 为 127.0.0.1**，仅本机 Nginx 可访问，更安全）：

```ini
[Unit]
Description=Penetrating Supervision Query System (FastAPI + Uvicorn)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/shenji/backend
Environment="PATH=/opt/shenji/venv/bin"
Environment="LANG=zh_CN.UTF-8"
ExecStart=/opt/shenji/venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 2
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
systemctl daemon-reload
systemctl enable shenji      # 开机自启
systemctl start shenji       # 立即启动
systemctl status shenji      # 绿色 active (running) 即正常
```

### 5.2 Nginx 开机自启

```bash
systemctl enable nginx       # 开机自启
systemctl restart nginx      # 重启加载配置
systemctl status nginx       # 确认 active (running)
```

常用运维命令：

```bash
# 后端
systemctl status shenji      # 状态
systemctl restart shenji     # 重启
journalctl -u shenji -f      # 实时日志
journalctl -u shenji -n 200  # 最近 200 行日志

# Nginx
nginx -t                     # 校验配置
systemctl reload nginx       # 平滑重载配置
tail -f /var/log/nginx/error.log    # Nginx 错误日志
```

### 5.3 放开防火墙端口（如启用了 firewalld）

```bash
firewall-cmd --permanent --add-port=80/tcp
firewall-cmd --reload
```

> 只需放开 **80 端口**（对外）；8000 端口仅本机 Nginx 访问，无需对外放开。
> 若系统未启用防火墙（`systemctl status firewalld` 显示 inactive/dead），可跳过此步。

# 服务器：替换并生效

## 八、常见问题排查


| 现象                                                      | 原因 / 处理                                                                                                                       |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `pip install` 报 `No matching distribution found for xxx` | 该包缺 aarch64 wheel。优先换纯 Python 替代品；或用附录 B 源码编译                                                                 |
| 启动报`ModuleNotFoundError: No module named 'aiomysql'`   | 依赖没装全或没用虚拟环境的 python。确认用`/opt/shenji/venv/bin/python`，重跑 4.2                                                  |
| 查询功能报连接 StarRocks 超时/拒绝                        | ①`telnet 10.9.14.128 9030` 测连通；② 检查服务器到 StarRocks 的防火墙；③ 核对 `.env` 账号密码（`#` 须为 `%23`）                 |
| 浏览器访问 80 端口打不开                                  | ①`systemctl status nginx` 看 Nginx 是否运行；② `ss -tlnp | grep :80` 看端口是否监听；③ 防火墙是否放开 80；④ `nginx -t` 看配置 |
| 页面能打开但接口 502/504                                  | 后端没起来。`systemctl status shenji`、`curl http://127.0.0.1:8000/api/health` 排查；导出超时则调大 Nginx `proxy_read_timeout`    |
| 登录后接口 401 频繁掉线                                   | `.env` 的 `JWT_SECRET` 是否设置；多 worker 时密钥须一致（本配置已统一）                                                           |
| 中文显示乱码                                              | systemd 已设`LANG=zh_CN.UTF-8`；如仍乱码，确认系统已安装中文字体/locale                                                           |
| `python3.12` 启动报 glibc 版本过低                        | UOS20 为 glibc 2.28，满足要求（python-build-standalone 需 ≥2.17）。`ldd --version` 确认                                          |
| 刷新页面 404                                              | 确认`/opt/shenji/frontend/dist/index.html` 存在，且 Nginx 配置含 `try_files $uri $uri/ /index.html`                               |
| `nginx -t` 报 80 端口冲突                                 | 未移除默认站点。`rm -f /etc/nginx/sites-enabled/default` 后 `systemctl reload nginx`                                              |

## 附录 B：离线 wheel 安装（备选）

> 仅当临时联网期间无法 pip 在线安装时使用。在【联网电脑】上预下载 aarch64 wheel，拷到服务器离线安装。

在 Windows 开发机 `backend` 目录执行（PowerShell 用反引号 `` ` `` 换行）：

```powershell
cd d:\2-code\shenji\backend

pip download -r requirements-server.txt `
  --platform manylinux_2_17_aarch64 `
  --platform manylinux2014_aarch64 `
  --platform manylinux_2_28_aarch64 `
  --python-version 312 `
  --implementation cp `
  --abi cp312 `
  --only-binary=:all: `
  -d wheels-aarch64
```

- 纯 Python 包（fastapi/sqlalchemy/aiomysql 等）下载 `py3-none-any` wheel；
- 二进制包（pydantic-core/cryptography/bcrypt/uvloop/httptools）下载 aarch64 wheel；
- 完成后 `wheels-aarch64/` 约 30 个 `.whl`，传到服务器（如 `/opt/wheels-aarch64/`）。

服务器上离线安装（`--no-index` 表示不联网，只从本地目录找包）：

```bash
/opt/shenji/venv/bin/pip install --no-index \
  --find-links=/opt/wheels-aarch64 \
  -r /opt/shenji/backend/requirements-server.txt
```

**某个包缺 aarch64 wheel 时：**

1. **优先换纯 Python 替代品**（如本方案用 aiomysql 替代 asyncmy 的思路）；
2. 或下载其源码包 `pip download somepkg --no-binary=:all: -d wheels-aarch64`，传到服务器编译安装
   （服务器已具备 GCC 7.3 + Make，多数 C 扩展可编译；python-build-standalone 自带 include 头文件）：
   ```bash
   /opt/shenji/venv/bin/pip install --no-index --find-links=/opt/wheels-aarch64 somepkg
   ```

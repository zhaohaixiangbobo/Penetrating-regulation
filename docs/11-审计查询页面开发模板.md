# 审计查询页面开发模板

用途：总结现有三个营销审计查询页面，并作为后续新增查询的需求、实现与验收模板。

核对日期：2026-09-30。现状依据工作区代码；“新增查询规范”表示后续开发约定。本文记录实现方式，业务结果准确性需要结合数据库样本核验。

### 1.1 短拜访记录

- 数据源：`crm_mcs_cust_visit_plan`，通过经理 UUID 关联 `t_comm_emp_yx` 获取公司、营业部、姓名。
- 有效拜访条件：`visit_status = '03' AND deleted = '0'`。
- 直接筛选单条记录时长，严格小于阈值，等于阈值的记录通过规则。
- 展示及导出：公司、许可证号、客户名称、营业部、客户经理、拜访日期、拜访时长（秒）。
- 日期快捷选项：今天、过去一个月、过去一年。

### 1.2 全商品缺访客户

当前 SQL 的分层方式：

| CTE | 职责 |
| --- | --- |
| `bf` | 在查询区间内按客户 UUID、月份统计有效拜访次数 |
| `list` | 关联评价主表、评价客户表和客户信息表，取得全商品客户及评价生效月 |
| `bg` | 按许可证号聚合指定变更记录，取最早决定月份 |
| `zh` | 关联拜访次数、许可证变更、`t_comm_employee` 人员归属 |
| 最终查询 | 筛选零拜访、指定公司及月份，排除已生效变更，按展示字段去重 |

- 评价条件：`evaluation_type_adj = '04'`、`a.status = '3'`、`y_m >= '2025-09'`。
- `y_m` 表示评价计算月份，固定业务起点；`sysupdatedate` 表示评价生效日期，决定输出月份和查询范围。
- 当前逐条评价记录取其生效月，形成“评价生效月缺访”结果；持续管理期间的逐月检查需要另行定义月历展开规则。
- 许可证处理：`handle_result IN ('02', '05')`，`apply_type IN ('07', '10', '12', '18')`，对应本次业务约定的歇业、停业整顿、收回、注销。
- 当前从 2025-09-01 起扫描许可证变更，按许可证号取 `MIN(decide_month)`；变更当月及后续月份排除异常。
- 最终保留条件：`decide_month IS NULL OR sqdate < decide_month`。先聚合再关联，使同一许可证的多次变更形成一条排除依据。
- 展示及导出：月份、公司、营业部、客户经理、客户编码、客户名称。接口月份为 `YYYYMM`，页面与 Excel 显示为 `YYYY-MM`。
- 月份快捷选项：上月、最近 3/6/12 个月。

### 1.3 客户经理日拜访不足

- 数据源：`crm_mcs_cust_visit_plan`，关联 `t_comm_emp_yx`。
- 有效拜访条件与功能 1 相同。
- 按日期、公司、营业部、经理 UUID、姓名分组，汇总原始秒数后执行 `HAVING` 阈值判断。
- 后端统一将 `tot`（秒）转为 `visit_minutes`（分钟），四舍五入到两位小数；页面固定显示两位小数。
- 展示及导出：拜访日期、公司、营业部、客户经理、拜访分钟数。
- 当前按记录日期汇总。工作日限定需要工作日日历及相应过滤；完全没有有效拜访记录的经理日期，需要补齐“人员 × 日期”后才能查出零拜访。

## 4. 新增查询的固定实现步骤

### 时长阈值选择规则（后续同类查询优先采用）

涉及“超过/不足多少秒或分钟”等时长判断时，优先增加时长阈值下拉选择，以原业务阈值作为默认值，选项围绕业务需求设置。例如单次超长拜访提供 260、280、300、320、340 分钟，默认 300 分钟。查询日期范围与拜访时长阈值分别展示。

- 前端标签和选项明确单位，请求参数按单位命名为 `threshold_minutes` 或 `threshold_seconds`。
- 选项及默认值写入需求卡；后端验证允许值，查询和导出使用同一参数及判断逻辑。
- 比较符遵循业务规则，按原始精度判断；例如“超过”使用 `>`，等于阈值时通过规则。分钟转秒在后端统一完成。
- 阈值进入已提交条件与缓存，返回页面恢复选择，重置恢复默认值；导出使用已提交阈值，并在文件名中标注阈值及单位。
- 页面说明使用“超过所选阈值（默认…）”等准确文案，随可选阈值功能同步更新。
- 共用 `AuditQueryPage` 可通过 `durationThreshold` 配置参数名、标签、单位、选项及默认值；查询请求与导出请求透传该字段。
- 最小验证覆盖默认值、允许选项、非法值、阈值相等及相邻边界、查询与导出一致性。

### 第一步：确认业务 SQL

1. 明确结果粒度和公司/人员归属，核对关联是否扩大行数。
2. 将公司、查询时间、人员、阈值改为参数；固定业务起点保留独立命名。
3. 明确阈值单位和 `< / <= / > / >=`，在原始精度上判断，展示时再格式化。
4. 日查询覆盖结束日，月查询覆盖结束月；月参数统一为 `YYYY-MM-01`，后端验证或归一化。
5. 历史状态排除按业务有效区间处理。对多条排除记录，采用已聚合的一条状态依据或 `NOT EXISTS`。
6. 采用明确的唯一键和稳定排序，分页排序在主排序字段后追加足以区分每行的键。

### 第二步：定义后端契约

- 日期查询继承 `AuditQueryRequest`；月份查询可参考 `MonthlyQueryRequest`，按业务命名单独模型。
- 定义 `<Name>Request`、`<Name>Row`，字段和 SQL 输出别名一致。
- 页码从 1 开始，默认每页 20 条、最大 200 条，响应复用 `Paged[<Name>Row]`。
- 新增 `_SQL_<NAME>_TMPL`、排序字段白名单和 `_build_<name>_query`。
- 分页端点复用 `_run_paged`；导出端点复用 `_run_all`。
- 存在秒转分钟等转换时，提取统一的行转换函数，分页和导出共同调用。
- 沿用审计路由登录校验；公司级授权接入时，查询、导出与元数据统一使用后端核定的范围。

固定接口形式：

```text
POST /api/audit/<query-key>
请求 = 已提交的业务筛选条件 + page/page_size + sort_field/sort_order
响应 = { total, page, page_size, items: Row[] }

POST /api/audit/<query-key>/export
请求 = 相同的业务筛选条件 + 相同排序
响应 = Row[]（遵守导出条数上限）
```

### 第三步：定义前端 Service

在 `frontend/src/services/audit.ts` 增加与后端一致的请求/行类型及两个函数：

```text
query<Name>(payload)  → request<Paged<Row>>，POST 查询端点
export<Name>(payload) → request<Row[]>，POST 导出端点
```

公司参数用 `com_ids: string[]`，人员精确筛选优先用 `person_uuid`；日期字符串用 `YYYY-MM-DD`，月份参数用 `YYYY-MM-01`。具有不同业务条件的查询定义独立请求类型。

### 第四步：实现页面

- 明细日期查询参考 `ShortVisit`；日期汇总查询参考 `DailyUnderHour`；月份查询参考 `FullCustMiss`。
- 使用 `PageContainer + QueryFilter + ProTable`，标题和副标题直接说明异常规则。
- 复用公司多选、人员联动、标签颜色、Excel 工具；业务筛选同时传入查询和导出。
- 用已提交条件驱动请求；再次查询时从第一页加载，重置时同步清空提交条件、缓存待恢复状态及人员选择。
- 分页和排序交给后端；缓存包含筛选、排序、每页条数及第一页结果，并按用户身份隔离。
- 查询范围或业务口径变化时更新缓存版本；退出或切换账号时清理相应缓存。
- 使用稳定的业务主键作为 `rowKey`。保留查询加载状态、导出加载状态、空数据提示与统一请求错误提示。
- 导出沿用已提交筛选和当前排序，明确展示达到导出上限时的提示。
- 时间、单位、月份和空值在表格与 Excel 中采用一致含义；格式化共用函数。
- 沿用全局样式和现有浏览器兼容配置。

以上是新增查询规范。其中第一页重置、完整重置、排序缓存、用户隔离、加载状态及导出上限提示，需要在新页中明确实现；当前三页的相关差异见第 6 节。

### 第五步：登记菜单与文档

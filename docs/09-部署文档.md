# 穿透式监督查询系统 · 更新部署操作手册

> 本文档面向**日常更新发布**：你在开发机改完代码后，把更新发到已部署的生产服务器需要做的操作。
>
> - **首次全新安装**（装 Python/依赖/Nginx/systemd）不在本文范围，见通用安装说明或《`docs/07-信创服务器部署手册.md`》。
> - 已假设服务器按既有约定部署：代码在 `/opt/shenji`，虚拟环境 `/opt/shenji/venv`，后端由 systemd 服务 `shenji` 守护（127.0.0.1:8000），前端 `dist` 由 Nginx 托管在 `/opt/shenji/frontend/dist`。
> - 仓库地址：`https://github.com/zhaohaixiangbobo/Penetrating-regulation.git`。

---

## 一、更新总流程一图

```
   开发机（Windows）                         生产服务器（Linux）
 ┌────────────────────┐   git push      ┌──────────────────────────┐
 │ 1. 改代码 + 本地自测 │ ──────────────▶ │  GitHub 仓库              │
 │ 2. 前端 npm run build│                 └───────────┬──────────────┘
 │ 3. git commit/push   │      git pull               │
 │ 4. 传 dist（前端改动）│ ───────────────────────────▶│ /opt/shenji
 └────────────────────┘   scp dist                    │
                                                       ▼
                                    5. (依赖变了) pip install
                                    6. systemctl restart shenji  （后端改动）
                                    7. 覆盖 dist + reload nginx   （前端改动）
                                    8. 验证
```

> 关键判断：**改了后端 → 重启 `shenji`；改了前端 → 换 `dist` 并 `reload nginx`；都改 → 两样都做。** 结构/账号/依赖/配置的额外动作见第四节。

## 二、开发机：推送前要做的

### 2.1 后端有改动：先本地自测

```powershell
cd d:\2-code\shenji\backend
D:\3-anaconda\envs\py312\python.exe -m pytest -q        # 跑单元测试
# 或临时起服务手动点：
D:\3-anaconda\envs\py312\python.exe -m uvicorn app.main:app --reload --port 8000
```

### 2.2 前端有改动：构建产物

```powershell
cd d:\2-code\shenji\frontend
npm run build            # 产物在 frontend/dist/（不进 Git，需单独传服务器）
```

### 2.3 提交并推送

```powershell
cd d:\2-code\shenji
git add .
git commit -m "本次更新说明"
git push origin main
```

> `.gitignore` 已排除 `backend/.env`、`backend/data/`、`frontend/dist/`、`node_modules/` 等，`push`/`pull` 都不会动服务器的配置与数据。

## 三、服务器：按“改了什么”执行

登录服务器：`ssh root@<服务器IP>`（更新期间需临时联网以 `git pull` / 装依赖）。

### 场景 A：只改了后端代码

```bash
cd /opt/shenji
git pull origin main
systemctl restart shenji
systemctl status shenji           # active (running) 即正常
```

### 场景 B：只改了前端

```powershell
# 开发机：构建后传输（已在 2.2 构建）
scp -r d:\2-code\shenji\frontend\dist root@<服务器IP>:/opt/shenji-frontend-dist
```

```bash
# 服务器：替换并生效（Nginx 无需重启，reload 即可）
rm -rf /opt/shenji/frontend/dist
mv /opt/shenji-frontend-dist /opt/shenji/frontend/dist
systemctl reload nginx
```

### 场景 C：前后端都改

先做**场景 A**（pull + 重启后端），再做**场景 B**（换 dist + reload nginx）。

## 四、需要额外动作的更新（对号入座）

### 4.1 改了数据库结构（新增表 / 新增字段）

**通常无需手动操作**：后端启动时会自动 `create_all` 建齐新表，并 `ensure_sqlite_schema` 幂等补齐新列。所以场景 A 的 `systemctl restart shenji` 就完成了结构迁移。

如需（重新）确保内置账号或结构，可另跑一次幂等初始化：

```bash
cd /opt/shenji/backend
/opt/shenji/venv/bin/python -m scripts.init_db
```

### 4.2 新增了 Python 依赖（`requirements-server.txt` 变了）

```bash
cd /opt/shenji
git pull origin main
/opt/shenji/venv/bin/pip install -r /opt/shenji/backend/requirements-server.txt
systemctl restart shenji
```

### 4.3 新增了 `.env` 配置项

`.env` 不在 Git 中、不会被 `git pull` 更新。若本次代码新增了配置项，需手动补到服务器的 `.env`：

```bash
vi /opt/shenji/backend/.env      # 参照 backend/.env.example 补上新增项
systemctl restart shenji
```

### 4.4 涉及“审计线索反馈附件上传”（仅首次配置一次）

线索附件单文件上限 10MB，而 **Nginx 默认请求体上限仅 1MB**，会导致上传返回 413。确保站点配置里有（`/etc/nginx/conf.d/shenji.conf` 的 `server` 块内）：

```nginx
client_max_body_size 20m;
```

改完 `nginx -t && systemctl reload nginx`。此项配置一次即可，后续更新无需重复。

> 附件实体存放在 `backend/data/uploads/clues/`，随 `data/` 一起被 `.gitignore` 忽略，`git pull` 不影响，无需处理。

## 五、账号维护

- 内置账号（`scripts/init_db.py` 预置，幂等）：
  - `admin` / `Tjyc!2026` —— 角色 **admin**（可进入「线索管理」、处理线索、下载任意附件）
  - `user` / `Tjyc!2026` —— 角色 **user**（提交线索、查看「我的线索」、营销审计查询）
- 新增/修正预置账号：编辑 `scripts/init_db.py` 里的 `SEED_USERS` 列表后，服务器 `git pull` 再跑：

  ```bash
  cd /opt/shenji/backend
  /opt/shenji/venv/bin/python -m scripts.init_db
  ```
- 把某个已有账号提升为管理员：在 `SEED_USERS` 中把其角色设为 `admin` 后重跑 `init_db`（幂等会自动修正角色），该账号重新登录后即可见「线索管理」。

## 六、每次更新后的验证清单

- [ ] `systemctl status shenji` 与 `systemctl status nginx` 均为 active (running)
- [ ] `curl http://127.0.0.1:8000/api/health` 返回 `{"status":"ok"}`（直连后端）
- [ ] `curl http://127.0.0.1/api/health` 返回 `{"status":"ok"}`（经 Nginx）
- [ ] 浏览器 `http://<服务器IP>` 能登录，本次改动点功能正常
- [ ] 前端有改动时：**强制刷新（Ctrl+F5）**避免旧缓存；查询页 F5 不 404
- [ ] 涉及附件时：普通用户能上传 > 1MB 文件（验证 `client_max_body_size` 生效）

## 七、回滚（更新出问题时）

```bash
cd /opt/shenji
git log --oneline -n 5            # 找到上一个正常版本的 commit
git reset --hard <上一个正常commit>
# 若依赖有变，回滚后按需重装：pip install -r backend/requirements-server.txt
systemctl restart shenji
```

前端回滚：保留上一版 `dist` 备份，或用对应 commit 重新 `npm run build` 后再传输覆盖。

> 数据安全：回滚只影响代码，`data/`（账号 + 线索 + 附件）与 `.env` 不受影响。重要更新前建议先备份 `backend/data/`（含 `app.db` 与 `uploads/`）。

## 八、常见问题（快速）

| 现象               | 处理                                                                             |
| ------------------ | -------------------------------------------------------------------------------- |
| 前端改了但页面没变 | 浏览器旧缓存。Ctrl+F5 强刷；确认 `dist` 已替换且 `systemctl reload nginx` 执行过 |
| 接口 502/504       | 后端没起。`systemctl status shenji`、`journalctl -u shenji -n 200` 查错          |
| 附件上传 413       | Nginx `client_max_body_size` 未设 20m（见 4.4）                                  |
| 启动报缺某个包     | 依赖没装：`/opt/shenji/venv/bin/pip install -r backend/requirements-server.txt`  |
| `git pull` 冲突    | 服务器不应手改仓库文件；如有本地改动 `git stash` 后再 pull                       |
| 新增配置项不生效   | `.env` 未补新增项（见 4.3），或未重启后端                                        |
